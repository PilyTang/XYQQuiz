# 2026-09-08：中文路径、退出、OCR 与教师节图标

## 中文路径

科举布局的 `validate_anchor_templates()` 使用 `cv2.imread(str(path))`。Windows OpenCV 文件名接口不能可靠读取中文路径；教师节图标已经使用字节解码，因此旧版 headless 自检会通过，正常启动却可能报科举 anchor 不可读。

修复为 Python 读取文件字节后调用 `cv2.imdecode()`，校准工具同步处理。自检增加 `recognition-layouts`，覆盖所有启用的科举布局和 anchor。回归将布局和图标复制到包含中文与空格的目录后，实际检测图面。

已重建开发试用包并首次解压到中文加空格目录，冻结 EXE 自检 9 项通过、交互 WGC 按 headless 模式跳过。新增科举资源项实际通过。报告：`docs/evidence/2026-09-08-chinese-path-self-test.json`。试用包沿用 `0.4.1-beta.1` 版本号，但构建标识是 `working-tree-20260908-path-shutdown`，不是此前 GitHub Beta 附件。

本轮全量测试 668 passed、3 skipped；随后对新增科举自检调用的修正与回归单独验证，selftest 专项 5 passed。三个跳过项仍为未提交的私人完整截图。

## 窗口退出

常规本机 WebView2 窗口关闭可正常退出，尚未取得用户残留进程的日志。已修复两个明确的退出风险：

- Uvicorn 原先无限等待连接及后台请求结束。现在最多等待 3 秒，再取消未完成请求并执行 lifespan 清理。
- 窗口关闭事件原先先通知原生预览 IPC，再设置服务器退出标志。现在先通知服务器退出，使捕获清理可以终止辅助进程，避免 IPC 阻塞导致退出尚未开始。
- 等待服务器清理的期限由 5 秒改为 20 秒，以容纳捕获、性能探测、OCR 等已有清理步骤。不会把线程设为 daemon 来掩盖未清理资源。

如果现场是 OCR 原生调用永久阻塞，线程本身不能被 Python 安全取消，仍需依据残留线程栈定位；这轮修改不能证明已消除所有第三方原生阻塞。

实机验证另增加一个永不返回的异步 HTTP 请求：确认请求已进入后关闭真实 WebView2 窗口，主函数返回 0，测试进程消失。未以强制终止进程来获得该通过结果。

## 14px 宋体与 PP-OCRv6

检查 GitHub `v0.4.1-beta.1` 下载 ZIP 内 `_internal/rapidocr/config.yaml` 及模型资源，检测与识别已经采用 **PP-OCRv6 small**，方向分类是旧版本轻量分类器。不能将本次优化描述为从 v5 升级到 v6。

使用仓库中四题的 16 个真实按钮裁剪，保持模型与文本行切分一致，对比结果：

| 输入 | 正确选项文字 / 总数 |
| --- | --- |
| 原始彩色 | 15 / 16 |
| 灰度阈值 90 | 13 / 16 |
| 灰度阈值 120 | 12 / 16 |
| 灰度阈值 150 | 14 / 16 |
| 保留灰度边缘的对比度拉伸 | 16 / 16 |

拉伸将灰度 40～170 映射到 0～255，修正了“鷹击”为“鹰击”。这只证明当前小样本受益；不能据此声称所有 14px 宋体、DPI、颜色和背景上均提升。硬二值化会破坏细笔画与抗锯齿边缘。尚未把实验预处理设为生产默认，也没有用技能名词典强改 OCR。

复现：`.venv\Scripts\python.exe scripts\benchmark_small_text.py`，生成 `build/small-text-benchmark.json`。原始测量见 `docs/evidence/2026-09-08-small-text-benchmark.json`。

后续评估应加入独立完整游戏帧、不同背景与 DPI，用字符错误率、整选项正确率、错框率和耗时共同判定；有实际字体渲染样本后，可增加同渲染方式的训练数据，不能仅靠字体名称认定所有像素一致。

官方模型说明：https://www.paddleocr.ai/main/version3.x/algorithm/PP-OCRv6/PP-OCRv6.html
