# v0.4.1 Beta 1 开发交接

本文面向只拿到 Git 仓库的新开发者。完成本页步骤后，不需要当前开发机上的临时目录、原始反馈截图或已构建便携包，即可继续开发、运行测试并重新构建 v0.4.1 Beta 1。

## 版本状态

- 应用版本：`0.4.1-beta.1`，GitHub Pre-release 标签为 `v0.4.1-beta.1`。
- 开发分支：`codex/v0.4-teachers-day`。
- 基线版本：`v0.3.1`。
- 支持活动：科举、教师节“看图说话”，运行时自动判断活动。
- 目标环境：Windows 10 1903 及以上或 Windows 11，x64，Python 3.11。
- 教师节优先适配 1024×768 及以上游戏画面。

如果该分支尚未合并到 `main`，克隆后必须显式切换分支：

```powershell
git clone https://github.com/PilyTang/XYQQuiz.git
Set-Location XYQQuiz
git fetch origin
git switch --track origin/codex/v0.4-teachers-day
```

合并后，直接检出 `main` 即可。若只需要运行程序，不需要开发环境，应从 GitHub Release 下载便携 ZIP；源码仓库不提交构建产物。

## 建立开发环境

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install --require-hashes -r requirements-release.txt
.venv\Scripts\python.exe -m pip install --no-build-isolation --no-deps -e .
.venv\Scripts\python.exe -m pip install "pytest==8.4.2" "pytest-asyncio==0.26.0"
Copy-Item config.example.json config.json
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\xyq-quiz.exe --config config.json
```

`config.example.json` 使用仓库内的相对路径。首次运行会在本机生成可变状态；这些文件由 `.gitignore` 排除。开发依赖也可以使用 `.venv\Scripts\python.exe -m pip install -e ".[dev,release]" 安装，但 CI 与正式构建以带哈希的 `requirements-release.txt` 为准。

教师节内置数据包含 336 条图标记录。`current.json` 指向完整 generation；更新器只有在记录、图片和摘要全部校验成功后才原子切换指针，失败时继续使用旧 generation。不要直接覆盖当前 generation 中的单个文件。

当前源码的匹配器 `teachers-day-0.4.1-2` 已根据后续反馈移除显式技能名映射。名称精确对应时沿用原判定；图标证据强且唯一、只有一个选项存在一处文字差异并明显领先其他选项时，返回 `CANDIDATE`，显示弱框并计入文字相似度。模糊匹配不能升级成高可信，也不能覆盖另一已知技能名。多个接近选项或图像歧义仍拒绝。规则与回归边界见 `docs/teacher-fuzzy-candidates.md`。

## 验证与隐私边界

当前源码在 Windows 11 x64 上的全量结果为 `666 passed, 3 skipped`。三个跳过项依赖没有提交到仓库的私人完整截图。包含文字近似匹配的开发试用包已通过 headless 自检，详见 `docs/teacher-fuzzy-candidates.md`；正式 Beta 仍需由 GitHub Actions 从标签提交重新构建、自检。机器变化或后续改动后应重新运行测试，不能把本页数字当作新提交的验证结果。

仓库只保留脱敏的小范围定位锚点，以及四题反馈中裁出的技能图标和选项按钮。原始截图包含游戏角色、聊天或账号环境，不得加入 Git。`scripts/check_public_tree.py` 会检查已跟踪文件中的私人路径、密钥、发布二进制和私人科举 fixture；提交前必须运行：

```powershell
.venv\Scripts\python.exe scripts\check_public_tree.py
git diff --check
.venv\Scripts\python.exe -m pytest -q
```

真实活动的长时间连续答题、全部 DPI/窗口组合和 Windows 10 实机仍需继续验收。反馈的四张图片只包含裁剪后的答题区域，因此本轮回归能够验证 OCR、名称兼容和图标匹配，不能单独证明完整游戏窗口定位。

## 构建和发布

构建完整便携包还需要安装 Visual Studio 的“使用 C++ 的桌面开发”工作负载与 Windows 10/11 SDK。脚本通过 `vswhere` 自动发现已安装的 C++ 工具集和 SDK；不要求当前开发机的 Visual Studio 安装目录。正式包必须从干净提交构建，并将提交 SHA 写入构建清单：

```powershell
.\scripts\build-release.ps1 -Version 0.4.1-beta.1 -Commit (git rev-parse HEAD)
```

构建输出位于本机 `release/`，不进入 Git。推送 `v0.4.1-beta.1` 标签会触发 `.github/workflows/release.yml`：校验标签与应用版本、许可证和公开树，运行全量测试，构建并自检便携包，再创建包含 ZIP 与 SHA-256 文件的 GitHub Pre-release。带 `alpha`、`beta` 或 `rc` 后缀的版本不会被标记为 Latest。

Beta 可以直接从已经验收的开发分支提交发布，无需先合并 `main`。稳定版推荐发布顺序：

1. 推送 `codex/v0.4-teachers-day` 并创建 Pull Request。
2. 等待 Windows CI 的公开树审计和全量测试通过。
3. 合并到 `main`，在新的干净克隆中复验。
4. 收集 Beta 反馈并完成验收后，将应用版本改为 `0.4.1`，从 `main` 上的对应提交创建并推送 `v0.4.1` 标签。

不要在分支尚未合并或 CI 未通过时提前推送正式标签。
