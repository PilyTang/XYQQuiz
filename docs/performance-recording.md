# 实机耗时记录

点击“开始性能记录”，正常连续答 30～50 题，点击“停止性能记录”，再点“导出耗时报告”。界面显示导出文件在本地 diagnostics 目录中的路径，ZIP 包含逐题 report.json、中位数/P95/最大值 summary.csv 和指标说明。

默认关闭，不持久化开关；停止后保留当前数据，可重复导出。重新开始会清空上一轮内存数据，退出程序前请导出。最多记录 500 题或 2000 次识别尝试，达到上限自动停止。

记录只包括时间、题目序号、活动类型、画面尺寸、后端标识、档位、结果等级、缓存命中、重试次数和逐选项 OCR 调用/回退次数。不保存截图、像素特征、题干、选项、答案、窗口标题、设备名称、配置全文或日志。未答出的题仍在 report.json 中，不能只看成功题的耗时汇总。

关键指标：

- capture_to_layout_start_ms：最终稳定题面的第一张捕获帧到开始定位，包含帧发布、轮询和协调等待。
- first_layout_ms：上述第一帧的布局定位耗时。
- stability_wait_ms：第一帧完成布局定位到两帧稳定确认，包含后续取帧、定位和特征比较，不能当作纯定时器等待。
- first_queue_ms：稳定确认到首次识别任务实际开始，包含正在执行的旧任务和线程调度等待。
- attempts：每次识别的开始、结束、接受时间及 OCR/匹配耗时。选项记录分别给出排队和执行耗时，以及完整 OCR 回退次数。
- capture_to_answer_ms：捕获到题面至后台接受首个可显示答案，包括中间重试；不是纯 OCR 耗时。
- received：前端收到状态后的回执。
- canvas_submitted：可见的软件预览提交画框并进入浏览器动画帧回调后的回执。
- native_command：原生预览画框 API 返回成功后的回执。

服务器统一使用高精度单调时钟；导出时换算为相对首帧的毫秒。浏览器只传自己的耗时，不直接比较浏览器与 Python 的绝对时间。回执指标含回程传输和服务器调度；浏览器端 elapsed_ms 可帮助分离 UI 内部处理。原生画框指令受理和 Canvas 提交均不证明显示器已经呈现，不应写成精确“上屏耗时”。最小化、暂停预览、页面断线或结果被新题覆盖时可能没有绘制回执，缺失值不等于零。

第一张捕获帧之前的游戏渲染等待不在记录范围内。一直抖动、尚未通过稳定确认的题面不会产生正式题号；途中开启可能漏掉当前题，请从下一题起统计。首次进入/重新定位与连续换题按 entry_kind 分组；缓存命中无 OCR 尝试，重试不新增题号。报告为启用记录时的性能，额外回执会引入少量测量开销。
