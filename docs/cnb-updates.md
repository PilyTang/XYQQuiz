# CNB 更新与发布

公开入口为 https://cnb.cool/pilytang/XYQQuiz 。该仓库用于发布便携包与更新说明，源码可以继续保留在原仓库。

## 用户端

软件更新面板提供“自动检查更新”和“检查更新”。默认开启自动检查；建立本机会话后后台检查，运行期间每小时判断一次是否已超过 24 小时。网络请求最多每天一次，手动检查不受此限制。取消自动检查后仅手动操作联网；设置和上次结果保存在 `user-data/update-check.json`，不进入发布包。

程序匿名读取 CNB 公开 `main/latest.json`，不使用开发者令牌。失败保留上次结果并提示无法检查，不把网络错误当成已是最新版。发现新版显示说明、SHA-256 和 CNB 下载入口，用户自行下载、解压到新目录；程序不会替换自身或自动执行下载文件。

每次打开界面，首次自动检查结果（包括 24 小时内的缓存结果）若发现新版且无错误，会居中弹出更新提示，提供更新说明、“下载新版”和“稍后再说”。关闭后本次打开不再弹出；后续定时或手动检查只更新侧栏。关闭自动检查后不弹启动提示。已有其他弹窗或页面隐藏时，等待弹窗关闭或界面可见后再展示，不叠加弹窗。

版本源只接受正式版数字版本、限定项目的 HTTPS 下载地址和有效 SHA-256，并限制响应大小及请求时间。关闭更新检查不影响离线识别；自检及版本查询不会检查更新。

## 维护者发布

仅在用户明确要求正式发布更新时执行完整的 [正式发布流程](release-process.md)。普通修复、测试和本地打包不自动上传或更新线上 `latest.json`。本节是 CNB 操作细节，不构成发布授权。

先完成测试、构建和冻结包自检，再运行：

```powershell
.venv\Scripts\python.exe scripts\publish_cnb.py --package release\XYQQuiz-v0.5.8-win10-win11-x64.zip --notes docs\releases\v0.5.8.md --token-file C:\private\cnb-token.txt
```

令牌文件保存在仓库之外；需要此 CNB 仓库的内容读写和 Release 读写权限。也可通过环境变量 `CNB_TOKEN` 提供，不把值放在命令行或提交到 Git。`--prepare-only` 仅校验本地 ZIP、生成版本清单，不联网、不要求令牌。

脚本先克隆发布仓库，空仓库仅建立说明文件，然后创建草稿发行版并上传 ZIP、SHA-256。附件完成后发布发行版，匿名下载重新核对完整 SHA-256，最后提交 `latest.json`，避免向用户推送尚不可下载的版本。不会强推或覆盖已公开的同版本附件；已公开版本可重试验证并补发版本指针。并发 Git 推送冲突会报错，保留既有远端提交。

GitHub Release 工作流配置 `CNB_TOKEN` Secret 后，会在包验证及 GitHub 发布完成后同步 CNB；未配置则跳过，不影响原发布。安装包只使用匿名访问，令牌仅用于维护端上传。

仅在明确需要替换尚未对外分发的同版本包时，先备份旧 ZIP、校验文件和版本清单，再显式添加 `--replace-existing`。该参数会替换同版本附件和发布说明；默认发布仍不覆盖已公开附件。版本号未变时，已安装同版本的客户端不会将它识别为新版，需要手动重新下载。
