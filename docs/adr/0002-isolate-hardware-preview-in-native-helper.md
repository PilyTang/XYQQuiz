# 将 Windows 硬件预览隔离到 C++ 辅助进程

XYQQuiz 的 Windows 硬件预览后端由独立 C++ 辅助进程实现，该进程持有 WGC、Direct3D 与 H.264 硬件编码资源；Python 主程序继续负责 OCR、题库、状态、设置、WebSocket 和界面。硬件模式只进行一次窗口捕获，辅助进程在 GPU 路径上生成 30 FPS 低延迟预览流，同时仅按识别节拍向 Python 提供 CPU 可读的识别帧。选择独立进程而不是扩展当前 NumPy 捕获路径，是为了避免 30 FPS GPU 到 CPU 的画面回读，并让原生组件故障时能够隔离退出并回退现有 CPU 捕获和 JPEG 预览，而不把应用改写成 C++。

辅助进程与 Python 通过随机命名的双向 Windows 命名管道交换控制消息、H.264 编码块、关键帧请求和故障状态；CPU 可读识别帧使用双缓冲共享内存传递，并始终只保留最新帧。每次发布携带帧 ID、尺寸和捕获时间戳，Python 读取落后时旧识别帧被覆盖而不进入积压队列。

## Consequences

命名管道和共享内存沿用主程序的当前 Windows 用户安全边界：使用不可预测名称、仅允许当前用户访问，并在握手中校验协议版本和本次启动随机令牌。主程序负责辅助进程的启动、存活监测、超时、退出和资源清理；辅助进程崩溃、卡死或协议不兼容均按硬件预览故障处理。

从硬件预览回退 CPU 时，必须先停止或隔离辅助进程持有的捕获会话，再由 Python CPU 路径接管，不能长期保留两套并行窗口捕获。正常退出和重启切换同样必须回收管道、共享内存、捕获与编码资源。
