# 科举历史样本：对比度增强实测

2026-09-08。结论：**不适合将这组固定对比度参数全局启用**。教师节小样本的收益没有在科举样本上稳定复现；部分原本正确的字被改错，一帧从高可信降为弱候选。

## 样本与方法

- 在旧 `feature-quiz-assistant` 工程的私人 fixture 与 diagnostics 中找到 17 个候选帧，按文件 SHA-256 去重后为 16 帧。
- 其中 5 帧有人工核验的题库编号及答案选项，3 帧标注为非科举；其余 8 帧是历史诊断与捕获截图，没有完整人工逐字标注。
- 两种输入均定位出 11 个题面，对应 10 个不同题目。历史样本包含网页截图、实机截图、JPEG 压缩及不同尺寸，不代表全部都是未经缩放的 14px 像素。
- 使用当前 PP-OCRv6 small、同一套布局、文字行切分、题库和匹配阈值。原图定位保持不变，只更改送入识别器的像素。
- 增强参数与教师节实验完全相同：转灰度，将 40～170 线性映射到 0～255，保留中间灰度。分行失败时的整块 OCR 回退输入也采用同一增强。
- 两个识别器先预热，每帧各跑 3 次，共 96 次流水线调用；不同帧交替先运行原图或增强。只比较识别出题面的 33 次 OCR 耗时/方案。

## 结果

| 指标 | 原图 | 对比度增强 |
| --- | --- | --- |
| 人工标注的题号与答案均正确 | 5/5 | 5/5 |
| 已标注非科举帧不出答案 | 3/3 | 3/3 |
| 定位出的题面 | 11 | 11 |
| OCR 耗时中位数 | 84.20 ms | 79.59 ms |
| OCR 耗时平均值 | 93.10 ms | 95.26 ms |

16 帧的最终题库编号和选项位置均未改变。但 `live-keju-picture.jpg` 由 `HIGH` 降至 `CANDIDATE`，会改变提示框的可信等级。不能将“最终选项没变”解释为文字没有变差。

已对变化处回看实际裁剪：

| 场景 | 原图 OCR | 增强 OCR | 判断 |
| --- | --- | --- | --- |
| 明末四公子，B 项 | 吴伟业 | 吴售业 | 新增错字 |
| 明末四公子，A/D 项 | 冒襄 / 陈贞慧 | 冒 / 陈慧 | 新增漏字；该题原识别也有其他不完整文字 |
| 清明上河图，题干 | 御前 / 题目 / 风俗画 | 很前 / 魏目 / 风怡画 | 新增错字，可信等级下降 |
| 四羊方尊，B/D 项 | B祭祀的礼器 / D蒸煮的容器 | 祭祀的礼器 / 蒸煮的容器 | 减少按钮字母干扰 |

没有完整逐字人工标注，故不报告全体字符准确率或字符错误率；也不把旧 state.json 的 OCR 输出当作标准答案。耗时差异不支持稳定加速的结论。

## 工程决策与复现

保留当前生产预处理。若后续引入增强，应作为受控的重试候选，保留原图结果，对不一致情况继续使用弱候选判定；不能仅凭增强结果置信度较高就覆盖原结果。

使用 `scripts/benchmark_keju_contrast.py --corpus <旧工程根目录> --output <本地报告目录> --rounds 3` 复现。脚本使用私有原始截图，不将截图和带私人路径的详细结果提交 Git。输出 `results.json` 包含两种方案的完整文字、匹配结果、逐次耗时与样本摘要，`sample-XX/` 保留原图 OCR 裁剪供人工复核。
